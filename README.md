# Shaukhaloves Cake — QR-меню и система заказа

Mobile-first веб-приложение для заказа по QR-коду, созданное так, чтобы ощущаться как установленное приложение для заказа еды, а не как обычный сайт ресторана.

## Стек

Next.js 14 (App Router) · React 18 · TypeScript · чистый CSS · PWA-манифест.
Без Tailwind, без Redux — состояние корзины хранится в компактном React Context + `useReducer` (см. `context/CartContext.tsx`), чего вполне достаточно для текущих задач без подключения Zustand.

## Начало работы

Зависимости этого проекта **не были** установлены в среде генерации (из-за отсутствия доступа к сети), поэтому для первого запуска требуется один подготовительный шаг:

```bash
npm install
npm run dev

```

Затем откройте `http://localhost:3000/?table=7`, чтобы сымитировать сканирование QR-кода гостем за столиком №7. Если открыть приложение без параметра `table` (например, просто `http://localhost:3000`), отобразится «Столик не определён», при этом меню останется полностью доступным для просмотра согласно спецификации.

Каждый исходный файл был написан и проверен на синтаксис вручную (через парсер компилятора TypeScript), так как запустить `next build` без установки пакетов было невозможно. Поэтому выполните `npm run build` после загрузки зависимостей, и если что-то не скомпилируется — напишите мне замечание, и я сразу всё исправлю.

## Что реализовано (Этапы 1–6)

* Определение номера столика из `?table=` с сохранением в сессии и без повторных запросов
* Хедер, живой поиск на стороне клиента, однострочная прокручиваемая панель категорий
* Двухзонные карточки товаров (зона фото + белая зона с деталями), бейджи, адаптивная сетка на 2/3/4 колонки
* Нижняя шторка товара (bottom sheet): полное описание, вес, состав, аллергены, плашки КБЖУ, ненавязчивый допродаж напитков, кнопка действия «+ цена»
* Счётчики количества (`− 1 +`) прямо в карточках и внутри шторки
* Фиксированная плавающая панель корзины с учётом `env(safe-area-inset-bottom)`
* Шторка корзины → настоящий `POST /api/orders` → экран подтверждения с трекером статуса «Принят → Готовится → Готов», который **опрашивает (поллит)** `GET /api/orders/:id` каждые 5 секунд, отображая реальные изменения статуса, когда персонал обновляет заказ
* Веб-манифест + иконки + цвет темы для ощущения нативного автономного приложения (`public/manifest.json`, `public/icons/`)
* **Этап 6 — API-маршруты и слой данных:**
* `lib/db.ts` — слой данных в оперативной памяти (`getProducts`, `createOrder`, `listOrders`, `getOrder`, `updateOrderStatus`), спроектированный в точности как будущая версия на PostgreSQL/Supabase, поэтому замена бэкенда потребует переписать только этот один файл, не затрагивая маршруты и вызывающий их интерфейс
* `GET /api/products` — каталог блюд
* `GET /api/orders`, `POST /api/orders` — получение списка заказов и оформление нового заказа; итоговые суммы всегда пересчитываются на стороне сервера на основе каталога и никогда не берутся на веру от клиента
* `GET /api/orders/:id`, `PATCH /api/orders/:id` — чтение данных конкретного заказа (используется поллингом на экране подтверждения) и обновление его статуса (подготовлено для панели кухни в этапе 7, пока не вызывается из UI)
* `app/page.tsx` теперь является серверным компонентом: он запрашивает блюда через `lib/db` и отправляет меню напрямую в исходном HTML-коде вместо загрузки на клиенте с отображением скелетона
* `app/admin/page.tsx` считывает актуальные заказы и каталог через тот же слой `lib/db` (пока в режиме только для чтения)


**Важный нюанс:** хранилище `lib/db.ts` находится в памяти сервера. Это отлично подходит для локальной разработки (сохраняется при hot-reload через глобальный объект Node), но сбрасывается при перезапуске сервера и не разделяется между serverless-инстансами — ожидаемо для заглушки 6-го этапа, но не предназначено для деплоя в продакшен «как есть».

## Заготовки на будущее (Этап 7)

Маршрут `PATCH /api/orders/:id` уже принимает новый статус и сквозным образом взаимодействует с поллингом на экране подтверждения. 7-й этап заключается «всего лишь» в создании кнопок для персонала на странице `/admin`, которые будут его вызывать (Принять / Начать готовить / Готов), а также в настройке авторизации, чтобы маршрут не был публичным.

## Фотографии блюд

`public/images/*.png` представляют собой сгенерированные заглушки (мягкие градиенты в фирменных оттенках), так как реальные фотографии блюд не были предоставлены. Поместите реальные снимки под теми же именами файлов, указанными в `data/products.ts` — изменения в коде не потребуются.
